# 唤醒词灵敏度调优：方法、实测数据与结论

> 2026-11-22 沉淀。目标是把「小喵小喵」在快语速、方言口音、轻声下的漏检压下去，同时不引入误唤醒。本文记录可复现的调参方法和实测结论，下次改唤醒词或换模型直接参照，不用重新摸索。

## 一、结论先行

| 项 | 改前 | 改后 |
|---|---|---|
| 关键词文件 | 1 行（标准音） | 2 行（标准音 + 「小」读四声） |
| `keywords_score` | 2.0 | **1.0** |
| `keywords_threshold` | 0.25 | **0.35** |
| `max_active_paths` | 4 | **8** |
| 正样本命中 | 36/47 | **47/47** |
| 误唤醒 | 4/21 | **0/21** |

三句话总结：

1. **漏检的主因不是阈值不够低，而是音素路径不同**——方言把某个字读成别的声调时，解码器根本走不到那条路径，调阈值无效。
2. **`keywords_score` 调高是负优化**。原配置的 2.0 同时降低了命中、并带来了误唤醒；正确方向是降到 1.0。
3. **`max_active_paths` 必须是 8**。写多条关键词时，4 条路径会被第一条占满，第二条等于白写。

## 二、配置事实

| 项目 | 值 |
|---|---|
| 引擎 | sherpa-onnx v2.0.2（Kotlin AAR） |
| 模型 | zipformer2 transducer，int8，`assets/kws/*.int8.onnx` |
| 音素表 | `assets/kws/tokens.txt`，227 项 ppinyin（声母 + 带声调韵母） |
| 关键词文件 | `assets/kws/keywords.txt` |
| 检测器 | `WakeDetector.kt`（`KeywordSpotter`） |
| 采样率 | 16 kHz 单声道 |

关键词文件每行格式：

```
<音素序列> :<keywords_score> #<keywords_threshold> @<中文标签>
```

当前内容（注：文件是 CRLF 行尾，实测不影响解析）：

```
x iǎo m iāo x iǎo m iāo :1.0 #0.35 @小喵小喵
x iào m iāo x iào m iāo :1.0 #0.35 @小喵小喵
```

一个汉字要拆成「声母 + 带声调韵母」两个 token：`小` → `x` + `iǎo`，`喵` → `m` + `iāo`。音节必须存在于 `tokens.txt`，否则该行直接被判为非法关键词。

## 三、为什么调阈值治不了口音

阈值（`keywords_threshold`）判断的是「当前这条音素路径的累计置信度是否过线」。它只在**路径已经存在**的前提下起作用。

方言口音改变的是声调，而声调写在 token 里（`iǎo` / `iào` 是两个不同 token）。也就是说，读错声调时解码器探索的是一条**不同的路径**，分数再低也不会被选成命中——阈值调到 0.10 也没用。

实测印证：阈值从 0.35 一路降到 0.10，命中数完全不动（都是 40/47）。所以正确做法是**把可能的读音变体都写进关键词文件**，而不是压阈值。

## 四、调参台

`scripts/tune-kws.py`，两个子命令：

```bash
# 首次造语料（约 1~2 分钟，之后复用）
python scripts/tune-kws.py corpus

# 扫变体 / 阈值 / boost，打印命中率与误唤醒
python scripts/tune-kws.py sweep --sets single,tone,short,full \
    --thresholds 0.35,0.30,0.25,0.20,0.15
```

### 语料构成

语料用 edge-tts 合成，落在 `.toolchain/kws-tune/corpus/`（约 4.9 MB，已 gitignore）。

正样本 47 条 = 7 音色 × 5 语速，再叠加音高漂移与轻声：

| 维度 | 取值 |
|---|---|
| 音色（7） | 晓晓（女/标准）、晓伊（女/活泼）、云希（男/年轻）、云健（男/浑厚）、云扬（男/播报）、**晓北（东北官话）**、**晓妮（中原官话）** |
| 语速（5） | -25% / -12% / +0% / +12% / +25% |
| 音高 | ±6%（4 条） |
| 轻声 | -12 dB、-18 dB（8 条） |

负样本 21 条 = 近音词 + 真实句子：

```
小喵 / 喵喵 / 小妙小妙 / 小苗小苗 / 喵小喵 / 小米小爱 / 今天天气不错我们出去走走吧
```

近音词按两个音色各合成一遍，所以是 7 × 3 = 21 条。

### 单行 vs 双行（boost 1.0，thr 0.35，paths 8）

## 六、几个容易踩的认知误区

**1. `keywords_score` 不是「灵敏度旋钮」，调高会同时伤命中率和准确率。**

它的作用是给该关键词路径加偏置。加太重会把近音词的置信度一起推过阈值。实测 1.5 和 2.0 都在同一批样本上误唤醒：

```
neg_2_xiaoxiaoneural / neg_2_yunxineural   ← 小妙小妙
neg_3_xiaoxiaoneural / neg_3_yunxineural   ← 小苗小苗
```

这两个词与「小喵小喵」的区别只是一个声母（miào / miáo vs miāo），偏置一高就分不开。

**2. `max_active_paths` 也不是越大越好。**

4 条路径时第二条关键词挤不进去（39/47，等于白加一条）；8 条刚好够两条关键词并存；**16 条反而冒出 4 条误唤醒**——活跃候选变多后，近音词的路径也活下来了，同上那两个词。

**3. 阈值安全区很窄。**

boost 1.0 时 0.25~0.35 是平台区（结果相同），0.45 掉 1 例。0.35 取的是平台区上沿，既保留余量又离掉点还有距离。

## 七、被否掉的方案

| 方案 | 实测效果 | 结论 |
|---|---|---|
| 加「喵→二声/三声」变体（`m iáo` / `m iǎo`） | 命中 46/47，但「小苗小苗」被判进来（2 条误唤醒） | 否决，收益不抵误唤醒 |
| 补两音节短词「小喵」做兜底 | 命中不涨，误唤醒涨到 8/21 | 否决，「小喵」是「小妙小妙」的前缀，必炸 |
| 阈值降到 0.10 | 命中数不变 | 无效，见第三节 |
| 提高 `keywords_score` 到 1.5~2.0 | 命中不升反降，误唤醒 4 条 | 负优化 |

## 八、落地与复核

改动位置：

| 文件 | 改动 |
|---|---|
| `assets/kws/keywords.txt` | 加四声变体行，boost 2.0 → 1.0，阈值 0.35 |
| `WakeDetector.kt` | `maxActivePaths` 4 → 8，`keywordsThreshold` 0.25 → 0.35 |
| `scripts/generate-keywords.sh` | 生成后自动 sed `x iǎo` → `x iào` 追加变体，boost 同步 1.0 |

Python 侧复核（与 App 用同一模型、同一关键词文件）：

```bash
xiaomiao_test.wav  → 命中「小喵小喵」
xiaodu_test.wav    → 未命中
```

**性能开销可忽略**：paths 4 → 8 时 RTF 从 0.021 升到 0.029（16 kHz 实时解码，1 秒音频约耗 29 ms），远低于实时。

## 九、后续想继续提的方向

这两条离线语料测不出来，得靠真机录音对比：

1. **换采集源**：监听态现在用 `VOICE_COMMUNICATION`，会走系统强降噪，可能削掉辅音（`x` 这类清擦音首当其冲）。换成 `VOICE_RECOGNITION` 关掉降噪再测。
2. **换更大的 KWS 模型**：当前是 `epoch-12 chunk-16 left-64` 的 int8 小模型，换更大的 zipformer 或非流式模型能提升鲁棒性，代价是内存与功耗。

## 十、踩坑记录

- **edge-tts 必须走代理**：`Communicate(..., proxy="http://127.0.0.1:7890")`。不加代理会卡住或报连接失败；`speech.platform.bing.com` 的 DNS 解析偶发失败，重跑一次即可。
- **合成后要转 16 kHz 单声道 PCM**：脚本内用 ffmpeg `-ac 1 -ar 16000 -c:a pcm_s16le`，否则采样率不匹配会导致全部漏检（假故障）。
- **喂完音频要补静音尾巴**：给流尾部追加约 0.66 s 静音再 `input_finished()`，否则末尾音节的尾音来不及落定，会假性漏检。
- **不同 `KeywordSpotter` 实例不能复用 stream**：每条样本新建 stream，测完 `del spotter` 释放（Python 侧的 `release()` 不存在，会报错）。
- **`selfTest()` 的样本是固定的**：「KWS 自检」播的是 `assets/greeting/xiaomiao_test.wav`（「小喵小喵」录音）。改唤醒词后自检必然报未命中，属预期行为，需同步替换样本。
